# Requests API v1

Base `/api`, JSON, existing session-cookie authentication. Feature is disabled until `REQUESTS_ENABLED=true` and `REQUESTS_SCHEMA_READY=true`. Use `GET /requests/capabilities` (always available) before showing entry points. New text is **plain text**, never HTML/Markdown interpreted by clients. Authenticated writes require `Content-Type: application/json` and `X-Shortcuty-Request: 1`; browser Origin, when supplied, must exactly match Shortcuty's existing origins. All responses `private, no-store`.

* `GET /requests?filter=open|solved|my&limit=20&before=<uuid>` → `{requests:[Request],next_cursor:null|uuid}`. `my` requires sign-in. Default open, max limit 50, cursor anchored to server ordering.
* `POST /requests` `{title,body,idempotency_key:<uuid>}` → `{request:Request}` (201). Title 3–120, body 1–5000 characters. New writes undergo deterministic spam controls and start Pending while text review is enabled. Pending content is visible only to its author and moderators. A current valid AI approval publishes benign text; uncertain or flagged content remains available for human review.
* `GET /requests/<uuid>` → `{request:Request}`.
* `PUT /requests/<uuid>` `{title,body}` (owner only). Edits clear acceptance, reopen and queue a fresh text review; an existing moderator Hidden hold remains. Points never reaward.
* `DELETE /requests/<uuid>` `{}` (owner only, including when an administrator is not the owner) → `{deleted:true,request_id:<uuid>,tombstone:{request_id:<uuid>,deleted_at:<ISO UTC>,recoverable:true}}`. Idempotent soft withdrawal hides the request and its discussion and cancels pending review/notifications. Earned points and the consumed award opportunity remain. Older clients may continue to consume only `deleted:true`.
* `GET /requests/<uuid>/tombstone` (owner only) → `{tombstone:{request_id:<uuid>,deleted_at:<ISO UTC>,recoverable:true}}`; no request text is returned. `POST /requests/<uuid>/restore` `{}` (owner only) → `{request:Request}`. Explicit recovery returns Open/Pending for fresh review, except that an existing moderator Hidden hold remains Hidden. Recovery cannot reaward points or replay cancelled notifications. Missing AI schema readiness returns 503. There is no automatic restore or purge timer.
* `GET /requests/<uuid>/comments?limit=20&before=<integer-id>` → `{comments:[Comment],next_cursor:null|id}`. Flat comments, oldest-to-newest; accepted comment separately pinned in Request, so pagination cannot lose it.
* `POST /requests/<uuid>/comments` `{body,idempotency_key:<uuid>,solution:null|{kind:"shortcuty",shortcut_uuid:<uuid>}|{kind:"icloud",url:"https://www.icloud.com/shortcuts/<32hex>"}}` → `{comment:Comment}` (201). body 1–3000. At most 2 solutions/request/user; max 1000 comments/request. Shortcuty solutions require currently approved/public shortcut and eligible author at every read/write/accept/delivery. iCloud URL is canonical HTTPS, no query/fragment/credentials/port, never fetched or executed. Sharing a link does not prove authorship.
* `DELETE /requests/<uuid>/comments/<id>` `{}` (comment author/admin); accepting a removed or hidden solution is forbidden. Removing an accepted solution reopens the request and clears the pin.
* `PUT /requests/<uuid>/vote` `{wanted:true|false}` → `{request:Request}`. Idempotent; “I want this too” does not follow or earn points.
* `PUT /requests/<uuid>/follow` `{following:true|false,muted:true|false}` → `{request:Request}`. Both fields required; idempotent. Explicit follow opts in to future notifications only; create/comment/vote never auto-follows. Unfollow/mute cancels pending delivery. Existing global `request_activity` notification preference also applies; absent preference defaults enabled **only for explicitly followed requests**.
* `POST /requests/<uuid>/accept` `{comment_id:<integer>}` → `{request:Request}` (requester/admin only). Comment must be a visible solution. Self-solving is permitted but earns no points. First nonself acceptance earns 10 nonmonetary points once per request. Reopening/reaccepting/reassigning cannot reaward or transfer an award. First self acceptance consumes the request's award opportunity. Moderators may reverse fraud; reversal is permanent and cannot free the award slot.
* `POST /requests/<uuid>/reopen` `{}` → `{request:Request}` (requester/admin).
* `POST /requests/<uuid>/reports` `{reason:"spam"|"abuse"|"unsafe_link"|"other",body:<0–1000>,comment_id:null|integer}` → `{reported:true}`. Repeated reports deduplicated per reporter/target.
* `PUT /requests/blocks/<user-id>` `{blocked:true|false}` → `{blocked:bool}`. Bidirectional Requests visibility/interactions/delivery; auth required. No preexisting backend account-block store was found in published baseline, so additive request-scoped adapter provides this until a common owner exists.
* `GET /users/<user-id>/request-reputation` → `{user_id,request_points,requests_solved}`. Counts eligible public accepted requests; points are summed audited awards (may persist after reopening), neither metric is a security endorsement.
* Admin: `GET /admin/requests/reports?limit=20`, `GET /admin/requests/pending?limit=20`, `POST /admin/requests/<uuid>/moderate` `{hidden:boolean,comment_id:null|integer,reason:<1–1000>}` → `{moderated:true}` (audited; approve pending with hidden false), `POST /admin/requests/<uuid>/reverse-award` `{reason:<1–1000>}` → `{reversed:true}` (audited once).

`Request`: `{id:<uuid>,title,body,status:"open"|"solved",moderation_status:"approved"|"pending"|"hidden",author:{id,username,profile_picture:null|"/uploads/<safe-relative-path>"},created_at:<ISO UTC>,updated_at:<ISO UTC>,wanted_count,comment_count,viewer:{is_owner,can_moderate,wanted,following,muted},accepted_comment:null|Comment}`.

`Comment`: `{id:<integer>,request_id:<uuid>,body,moderation_status,author:{id,username,profile_picture:null|"/uploads/<safe-relative-path>"},created_at:<ISO UTC>,solution:null|{kind,shortcut_uuid:null|uuid,url,review_status:"unreviewed"|"published_on_shortcuty"}}`. `published_on_shortcuty` describes publication, **never** security approval. Hidden/unavailable Shortcuty solution projects `solution:null`, no private metadata/URL; the request is projected open when its accepted solution becomes unavailable.

Request and Comment responses may include nullable `approval:{state,code,retry_at}` for their owner or a moderator. States are `queued|scanning|retrying|needs_review|failed|approved|cancelled`; `code` is a finite sanitized status code and `retry_at` is nullable ISO UTC. Provider prose, prompts and responses are not exposed. Public viewers receive no private review diagnostics. Publication is determined by `moderation_status`, not the job label. Older clients can ignore this additive field. A user's own approved open requests remain in Open, subject to ordinary visibility and pagination; Pending requests remain in My/owner detail.

Requests text review uses OpenAI `gpt-6.1-sol` only, independently of shortcut scanning. It does not fall back to Gemini or another model/provider. Only bounded request/comment text and proposed-link metadata are sent; links and workflows are not fetched or executed. Approval does not certify a proposed workflow's safety or authorship. Provider failures retry with backoff, at most five attempts per revision within 24 hours and two concurrent calls. Editing, withdrawal, account restrictions and human decisions prevent delayed results from publishing stale content. Pausing AI while retaining schema readiness holds new content Pending.

Errors `{error:<stable code>}`: 400 invalid input, 401 sign-in, 403 permissions/account capability/CSRF, 404 unavailable/blocked/hidden target, 409 conflicting idempotency key/state, 413 >16KiB payload, 429 rate/quota, 503 disabled/unready. Requests errors start `REQUESTS_`; existing authentication/account restriction guards keep their established response shapes. Native clients send the request header but do not need an Origin. No bearer-only route support is added.

Admission: 120 authenticated mutation attempts/hour/user, committed before the global gate even when a later action is denied. Initial limits: 3 new requests/day/user, 30 comments/day/user, 60 interaction writes/hour/user, 5 accept/reopen changes/hour/user, 10 reports/day/user; maximum 100 followers/request, 200 active follows/user; awards <=50 points/day/recipient and <=10 points/30days per requester/recipient pair. Exceeding award bounds rejects acceptance with 429 (no silent deferred award). A database singleton write gate serializes beta writes and awards across processes; separate per-account quotas persist across workers. No analytics/fingerprinting.

Notifications use durable per-event/per-recipient outbox, only explicit current followers, no actor/self notifications, no history. Pending comments hold only submission-time follower events; current AI or moderator approval releases those captured events within 24 hours, without enumerating later subscribers. Request approval creates no broadcast. Dispatch rechecks visibility, restrictions, follow generation and global preferences. Capability `notifications` is `inbox_only` or `inbox_and_push`. The activated push cohort captures only new activity for current eligible registered devices; existing inbox events, later followers and later devices are never replayed. Push follows the same account, follow/mute, visibility and notification preferences. Lock-screen copy is generic, with no authored request/comment text. Provider acceptance does not prove device display; OS permission is still required.

Avatar follow-up: request authors, comment/solution proposers and accepted solvers expose the same nested `author.profile_picture` field. It uses the existing `ModelHelper.public_profile_picture_url` validation and the same joined users row as the username; no extra profile/API queries. Missing or malformed paths are null. Existing avatar components should resolve the relative path through their current URL validation, still-avatar and cache behavior, use their normal fallback, and avoid announcing the username twice. Existing profile/points surfaces can keep their normal profile avatar. Blocked/deactivated author filtering is unchanged.
